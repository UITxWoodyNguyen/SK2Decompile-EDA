🛑 Hạn chế của Decompiler Luật Tĩnh (IDA Pro / Ghidra)

  • Dựa vào luật tĩnh cứng nhắc (heuristic AST pattern matching).
  • Mã giả sinh ra chứa đầy định danh vô nghĩa: v1, v2, a1, sub_1169.
  • Ép kiểu thô bạo (_QWORD, _DWORD), làm biến dạng con trỏ.
  • Hậu quả: Tốn rất nhiều thời gian dịch ngược thủ công của kỹ sư SOC/Malware Analyst.

⚠️ Điểm nghẽn của LLM Đơn Pha (LLM4Decompile)

  • Cố gắng dịch thẳng Assembly $\rightarrow$ Mã C hoàn chỉnh trong 1 lượt (End-to-End).
  • Mô hình bị quá tải (Overburdened): Vừa phải khôi phục cấu trúc điều khiển giải thuật, vừa phải phán đoán tên biến có nghĩa.
  • Xuất hiện ảo giác cú pháp (Syntax Hallucination).
  • Hậu quả: Tỷ lệ Re-executability sụt giảm nghiêm trọng ở mã tối ưu hóa cao (-O2, -O3).
🎯 Câu hỏi nghiên cứu:
Làm thế nào để vừa đảm bảo mã C khôi phục có thể biên dịch lại và chạy đúng (Executability), vừa khôi phục được định danh biến/hàm tự nhiên như con người viết (Readability)?

🦴 PHA 1: Khôi Phục Cấu Trúc (Skeleton)

Mô hình: sk2decompile-struct-6.7b
  • Đầu vào: Mã giả IDA / Assembly từ stripped binary.
  • Chuẩn hóa mọi định danh thành biến tạm chung: var1, var2, type1, func0.
  • Compiler-guided RL: Tối ưu hóa bằng phản hồi trực tiếp từ compiler nhằm tối đa hóa tính đúng cú pháp và CFG.
  • Đầu ra: Mã biểu diễn trung gian (Structure IR).

✨ PHA 2: Tái Tạo Định Danh (Skin)

Mô hình: sk2decompile-ident-6.7b
  • Đầu vào: Mã khung xương IR từ Pha 1.
  • Dự đoán định danh nghiệp vụ giàu ngữ nghĩa: numbers, buffer, len, count.
  • Semantic Similarity RL: Tối ưu bằng hàm thưởng tương đồng ngữ nghĩa (GPT-Judge) mà không làm lệch cấu trúc.
  • Đầu ra: Mã C hoàn chỉnh, dễ đọc cho con người.

1. Lỗi BPE Detokenizer

vLLM giải mã ánh xạ khoảng trắng thành Ġ, newline thành Ċ, tab thành ĉ.

Hậu quả nếu không lọc: GCC lập tức báo lỗi stray \304 in program, Re-compilation rơi về 0%.

2. Ngữ Cảnh 8192 & Safe Trimming

Tại mức -O2/-O3, loop unrolling và inlining khiến mã IDA vượt quá 6,000 tokens.

Giải pháp: Nâng max_model_len=8192 kết hợp cắt gọt an toàn loại trừ hoàn toàn nguy cơ CUDA OOM.

3. Chuẩn Hóa Header thay `psychec`

Thư viện psychec của tác giả thường xuyên bị Segmentation Fault trên struct phức tạp.

Giải pháp: Xây dựng bộ STD_HEADERS chuẩn kết hợp mock types giúp cô lập lỗi thuần túy do mô hình.

✅ Đã Khắc Phục (0.71% ➔ 27.51%)

  • Khử Token Collapsing: Tách các từ khóa bị dính: intlonglongfunc0, return1;, constchar, elseif.
  • Sửa hàm `restore_func_name`: Khắc phục lỗi regex cũ làm mất tên hàm func0 khi gặp dấu C++ ::.
  • Kết quả: Tỷ lệ Re-compilation lập tức đạt 52.73% (đạt ~65% con số tác giả).

🔎 Khoảng Cách Còn Lại (27.51% vs 69.00%)

  • Harness & Sanitizer độc quyền: Tác giả sử dụng pipeline nội bộ biến đổi AST và ép kiểu toán học chặt chẽ.
  • Độ suy thoái theo bậc tối ưu: Re-executability giảm từ 40.24% (-O0) xuống 14.16% (-O3) do loop unrolling và inlining tái cấu trúc hoàn toàn đồ thị CFG.
  • Semantic Drift: Mô hình đôi khi đổi kiểu số thực từ float sang double, khiến phép so sánh fabs() trượt unit test assertions.

    int var8, var9, var10;
    struct type1 var14;
    translog_interpret_file_header(&var14, var1);
    localtime_r(&var14.field1, &var14.field2);

✨ Pha 2: Identifier Recovery (Da thịt giàu ngữ nghĩa)

void dump_header_page(unsigned char *page) {
    unsigned long sec, arialog_version;
    int year, month, day;
    struct translog_file_header header;
    translog_interpret_file_header(&header, page);
    localtime_r(&header.timestamp, &header.tm);
    year  = header.tm.tm_year + 1900;
    month = header.tm.tm_mon + 1;
    day   = header.tm.tm_mday;

}

Case Study 2: Sửa Lỗi Token Collapsing Trên HumanEval-C
Hàm func0 (HumanEval-C-0, so sánh khoảng cách float)

❌ Lần Chạy 1: Lỗi Nuốt Dấu Cách (FAIL)

// Lỗi sáp nhập token:
intlonglongfunc0(float*x,intn,floateps){
    inti,j;
    for(i=0;i<n;i++){
        for(j=i+1;j<n;j++){
            if(fabs(x[i]-x[j])<eps){
                return1; // <-- Lỗi undeclared!
            }
        }
    }
    return0;
}
// GCC: unknown type 'intlonglongfunc0'
// Re-comp: FAIL | Re-exec: FAIL

✅ Lần Chạy Mới: Sau Khử Dính Token (PASS)

// Mã sau khi lọc qua Sanitizer:
int func0(float *x, int n, float eps) {
    int i, j;
    for (i = 0; i < n; i++) {
        for (j = i + 1; j < n; j++) {
            if (fabs(x[i] - x[j]) < eps) {
                return 1;
            }
        }
    }
    return 0;
}
// GCC: Biên dịch thành công 100%
// Re-comp: PASS | Re-exec: PASS (4/4 test cases)

1. Kiểm Chứng Kiến Trúc

Khẳng định phương pháp "Skeleton to Skin" hoàn toàn có cơ sở khoa học. Pha 2 có năng lực vượt bậc trong việc tái tạo tính dễ đọc (Readability) cho chuyên gia dịch ngược.

2. Khắc Phục Nghẽn Kỹ Thuật

Làm rõ nguyên nhân ban đầu chỉ đạt 0.71% do BPE detokenizer. Sau khi chuẩn hóa token, Re-compilation đạt 52.73% và Re-executability đạt 27.51% (O0 đạt 40.24%).
